Q: Which other xv6 system call(s) could be made faster using this shared page? Explain how.
A: The system call uptime() is the best candidate for this optimization. The system uptime (number of clock ticks since boot) is a global variable maintained by the kernel. Like the PID, it is read-frequently but written-only by the kernel. To implement this, we can add a field (e.g., uint64 ticks) to the shared usyscall structure. The kernel's timer interrupt handler would update this value in the shared page every time the hardware timer fires. The user space uptime() function would simply read this memory address instead of performing a system call. This eliminates the trap overhead for time-checking.

Q: For every leaf page in the vmprint output, explain what it logically contains and what its permission bits are.
A: A leaf page corresponds to a level-0 page table entry that directly maps a virtual address to a physical memory page in RAM. Leaf pages contain actual data used by the process, such as program code, stack, heap, global variables, trapframes, or the trampoline code. Each leaf page table entry must have at least one of the permission bits PTE_R, PTE_W, or PTE_X set, indicating whether the mapped memory is readable, writable, and/or executable. These permissions enforce memory protection and determine how the process may access each page.
